# IRremoteESP8266 for ESP-IDF

[IRremoteESP8266](https://github.com/crankyoldgit/IRremoteESP8266) v2.9.0 (tag `v2.9.0`), ported to ESP-IDF
without the Arduino framework. License: LGPL-2.1, see [LICENSE.txt](LICENSE.txt). `src/` is the library's
`src/` directory, with the changes listed below. Every change is marked with `IRREMOTE_ESP_IDF`.

## Changes to the library (src/)

-   `IRsend.h`, `IRsend.cpp`: with `IRREMOTE_ESP_IDF`, `mark()`, `space()` and `_delayMicroseconds()` do not drive
    the GPIO. They add RMT symbols (1 us resolution) to a buffer. `flush()` (also called by the destructor) sends
    the buffer with the RMT peripheral and waits until it has been sent. The carrier (frequency and duty cycle
    from `enableIROut()`) is generated by the RMT. A change of the frequency sends the collected symbols first.
    `begin()`, `ledOn()` and `ledOff()` do not touch the GPIO (the RMT channel owns it). New members:
    `~IRsend()`, `flush()`, `_rmt_symbols`, `_rmt_freq`, `_rmtAppend()`.
-   `IRremoteESP8266.h`: includes `<Arduino.h>` (the shim), the protocol headers include it only with `ARDUINO`.
-   `IRutils.cpp`: `dayToString()` uses `substr()` like in `UNIT_TEST` (String is `std::string`).
-   `IRrecv.h`, `IRrecv.cpp`: with `IRREMOTE_ESP_IDF` the timer and GPIO interrupt code (4 blocks) is left out,
    `enableIRIn()` / `disableIRIn()` do not capture anything (do not call `enableIRIn()`: its `pinMode()` would take
    the GPIO from the RMT). New `loadRaw()`: loads a message captured by the RMT RX channel (`ir_rmt_rx.h`), then
    `decode()` works as usual. Decoding is unchanged.

## Added files (port/)

-   `Arduino.h`: the small part of the Arduino API the library uses outside of its `UNIT_TEST` mode: `math.h`,
    `String` (`std::string`), `F()`, `micros()`, `millis()`, `delay()`, `delayMicroseconds()`, `pinMode()`,
    `digitalWrite()`, `digitalRead()`, `ESP.restart()`.
-   `ir_rmt_tx.h`, `ir_rmt_tx.cpp`: RMT TX channel (created with the first message), copy encoder, carrier
    (set before the channel is enabled, like the IR example of ESP-IDF), strongest GPIO drive (about 40 mA) for an
    IR LED without a transistor. Logs the carrier and the length and first durations of every message.
-   `ir_rmt_rx.h`, `ir_rmt_rx.cpp`: RMT RX channel for an IR receiver module (TSOP38238, VS1838B, ...),
    ping-pong (partial) receive, glitch filter, the end of a message is a space longer than the idle time.

## Protocols

Only the air conditioner protocol selected in menuconfig (`IR air conditioner` -> `Air conditioner protocol`)
is compiled: `_IR_ENABLE_DEFAULT_=false`, `SEND_<protocol>=true`, `DECODE_<protocol>=true` (see
`CMakeLists.txt`). The whole library does not fit into the OTA partition next to Matter. The definitions are
PUBLIC because they change the classes. `IR_AC_PROTOCOL_ENUM` is the `decode_type_t` of the protocol.

Sending happens in the task that calls it and blocks until the message has been sent (a few hundred ms for
an air conditioner message). Do not call it from the Matter thread.

## Updating the library

Copy `src/` of the new version and apply the changes above again (search for `IRREMOTE_ESP_IDF` in this
version).
